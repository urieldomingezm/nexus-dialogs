Migrar desde SweetAlert2

Dos caminos: cambiar solo el import y migrar poco a poco, o pasar directo a la API propia. Puedes mezclar los dos en el mismo proyecto.

Camino 1: cambia el import

El adaptador nexus-dialogs/swal acepta el mismo código que ya tienes: Swal.fire, mixin, toasts, inputs, preConfirm, pasos, timers y los métodos de consulta. Aplica el estándar de botones de la librería.

// antes
import Swal from 'sweetalert2'
// después
import Swal from 'nexus-dialogs/swal'

Sin bundler, cambia el <script> por este (define window.Swal):

<script src="https://cdn.jsdelivr.net/npm/nexus-dialogs/dist/nexus-dialogs.swal.iife.js"></script>

Camino 2: la API propia

Más corta, con tipos precisos y recetas ya hechas (confirmDelete, unsavedChanges, approval, bulkAction…). Cada ejemplo trae los dos botones: el primero corre el código de SweetAlert2 con el adaptador, el segundo la versión propia.

El resultado aparece aquí.

Confirmar un borrado

El caso más común. El adaptador pone el botón en rojo y el foco en «Cancelar» porque el texto dice «eliminar».

Antes: SweetAlert2

const r = await Swal.fire({
  title: '¿Eliminar a Laura Méndez?',
  text: 'No podrás revertirlo',
  icon: 'warning',
  showCancelButton: true,
  confirmButtonText: 'Sí, eliminar',
})
if (r.isConfirmed) await borrar(id)

Después: API propia

import { confirmDelete } from 'nexus-dialogs/patterns'

if (await confirmDelete({ what: 'a Laura Méndez' })) await borrar(id)

Aviso de éxito que se cierra solo

El timer se pausa con el mouse o el foco encima, y se respeta «reducir movimiento».

Antes: SweetAlert2

await Swal.fire({
  icon: 'success',
  title: 'Guardado',
  text: 'Los cambios ya están en el sistema',
  timer: 2500,
  showConfirmButton: false,
})

Después: API propia

import { dialog } from 'nexus-dialogs'

await dialog.success({ title: 'Guardado', text: 'Los cambios ya están en el sistema', timer: 2500 })

Pedir un dato con validación

inputValidator pasa a `validate`; el error queda ligado al campo y se anuncia a lectores de pantalla.

Antes: SweetAlert2

const { value: correo } = await Swal.fire({
  title: 'Correo del cliente',
  input: 'email',
  inputValidator: (v) => (!v ? 'Escribe un correo' : undefined),
})
if (correo) await enviar(correo)

Después: API propia

import { form } from 'nexus-dialogs/forms'

const r = await form({
  title: 'Correo del cliente',
  fields: [{ name: 'correo', label: 'Correo', type: 'email', required: true }],
})
if (r.confirmed) await enviar(r.value.correo)

Formulario con varios campos

En SweetAlert2 se arma con HTML y preConfirm leyendo el DOM. Aquí los campos son datos y la validación va por campo.

Antes: SweetAlert2

const { value } = await Swal.fire({
  title: 'Nuevo gasto',
  html: '<input id="rfc" class="swal2-input"><input id="importe" class="swal2-input">',
  focusConfirm: false,
  preConfirm: () => ({
    rfc: document.getElementById('rfc').value,
    importe: document.getElementById('importe').value,
  }),
})

Después: API propia

import { form } from 'nexus-dialogs/forms'

const r = await form({
  title: 'Nuevo gasto',
  fields: [
    { name: 'rfc', label: 'RFC del proveedor', type: 'rfc', required: true },
    { name: 'importe', label: 'Importe', type: 'money', required: true },
  ],
})

Varios pasos

progressSteps y `Swal.mixin().queue` pasan a un asistente con revisión final y progreso accesible.

Antes: SweetAlert2

const Pasos = Swal.mixin({ progressSteps: ['1', '2', '3'], confirmButtonText: 'Siguiente' })
await Pasos.fire({ title: 'Datos', currentProgressStep: 0 })
await Pasos.fire({ title: 'Puesto', currentProgressStep: 1 })
await Pasos.fire({ title: 'Prestaciones', currentProgressStep: 2 })

Después: API propia

import { wizard } from 'nexus-dialogs/forms'

const r = await wizard({
  title: 'Alta de empleado',
  review: true,
  steps: [
    { title: 'Datos', fields: [{ name: 'nombre', label: 'Nombre', required: true }] },
    { title: 'Puesto', fields: [{ name: 'puesto', label: 'Puesto', required: true }] },
    { title: 'Prestaciones', fields: [{ name: 'vales', label: 'Vales de despensa', type: 'switch' }] },
  ],
})

Aviso tipo toast

Los toasts comparten una cola y se anuncian en una región viva. Admiten acción «Deshacer».

Antes: SweetAlert2

Swal.fire({
  toast: true,
  position: 'top-end',
  icon: 'success',
  title: 'Empleado guardado',
  timer: 3000,
  showConfirmButton: false,
})

Después: API propia

import { toast } from 'nexus-dialogs/toast'

toast.success('Empleado guardado', { action: { label: 'Deshacer', onClick: deshacer } })

Operación larga con «Cargando…»

preConfirm async muestra «Procesando…»; si la promesa falla, el error aparece dentro del diálogo y no se cierra.

Antes: SweetAlert2

const r = await Swal.fire({
  title: '¿Enviar a timbrar?',
  showCancelButton: true,
  showLoaderOnConfirm: true,
  preConfirm: () => timbrar().catch((e) => Swal.showValidationMessage(e.message)),
})

Después: API propia

import { dialog } from 'nexus-dialogs'

const r = await dialog.confirm({
  title: '¿Enviar a timbrar?',
  preConfirm: () => timbrar(), // si lanza, el error se muestra y el diálogo sigue abierto
})

Qué cambia a propósito

  • Botones: Cancelar, Denegar, Confirmar, en ese orden; una confirmación que dice «eliminar» o «borrar» pasa sola a peligro, con el foco en Cancelar.
  • Colores y clases: confirmButtonColor y customClass se ignoran; los colores vienen del tema.
  • El contenido vive en un Shadow DOM: en lugar de document.getElementById('x') usa Swal.getHtmlContainer().querySelector('#x'). Tu CSS ya no lo rompe.
  • Idioma: los textos por omisión salen en el idioma configurado («Aceptar», «Cancelar»).
  • Sin equivalente: Swal.version, topLayer, showClass / hideClass y animation.

Lista de verificación

  1. Instala nexus-dialogs y cambia el import (o el <script>).
  2. Busca en tu código document.getElementById o querySelector dentro de html: y didOpen; cámbialos por Swal.getHtmlContainer().
  3. Quita customClass y confirmButtonColor; configura un tema una sola vez con configure.
  4. Revisa los diálogos de borrado: ahora el foco empieza en «Cancelar».
  5. Migra primero lo que más se repite (borrar, guardar, formularios) a las recetas y a form.
  6. Prueba con teclado: Tab, Esc y regreso del foco al botón que abrió el diálogo.
