nexus-dialogs vs SweetAlert2

SweetAlert2 es el estándar para alertas y confirmaciones, con años de uso. nexus-dialogs apunta a otra cosa: sistemas de empresa con formularios, validación y datos de México. Aquí está la comparación completa, incluido lo que a nexus-dialogs todavía le falta.

Comparado con SweetAlert2 11.26.25 (npm) y nexus-dialogs v.

Cuándo usar cada uno

Elige SweetAlert2 si…

solo necesitas alertas y confirmaciones; quieres la comunidad y el ecosistema más grandes; usas sus funciones visuales (imágenes, pasos de progreso, arrastrar, RTL); o ya lo usas y no tienes problemas de CSP, z-index ni CSS que se pisa.

Elige nexus-dialogs si…

construyes un sistema de empresa con formularios, asistentes, importación o RFC/CURP/CLABE; necesitas CSP estricta y aislamiento de CSS; te importa prefers-reduced-motion y el foco en acciones destructivas; o quieres migrar sin reescribir todo.

O los dos a la vez

No chocan: nexus-dialogs usa la capa superior del navegador y el Shadow DOM. Puedes migrar pantalla por pantalla.

Pruébalo lado a lado

El mismo escenario con SweetAlert2 real, con el adaptador (el mismo código, otro import) y con la API propia de nexus-dialogs.

Migrar en tres pasos

// 1. Cambia el import (el resto de tu código sigue igual)
// antes:  import Swal from 'sweetalert2'
import Swal from 'nexus-dialogs/swal'

// 2. Quita el CSS de SweetAlert2 si lo cargabas por separado.

// 3. Revisa la lista de abajo: lo que se ignora a propósito y lo que todavía no existe.
const r = await Swal.fire({ title: '¿Eliminar?', icon: 'warning', showCancelButton: true, confirmButtonText: 'Sí, eliminar' })
if (r.isConfirmed) borrar()

El adaptador pasa a tener el estándar de botones: con un texto como «Eliminar» o «Borrar» el botón principal sale en rojo y el foco queda en Cancelar. Después, pantalla por pantalla, puedes pasar a la API propia (confirmDelete, form…) para aprovechar lo que SweetAlert2 no tiene.

Qué cubre el adaptador

Contado contra la API real de SweetAlert2 y verificado por una prueba automática: si SweetAlert2 agrega algo, el CI avisa.

Lo que funciona a medias

    Lo que todavía le falta a nexus-dialogs

    Ordenado por lo que más se nota al migrar. Es la hoja de ruta.

    PrioridadQué faltaPor qué importa
    AltaAcceso al contenido del popup: getHtmlContainer, getTitle, getContainer… y una forma de que el código con document.getElementById siga funcionandoMucho código de SweetAlert2 arma el html y lo lee a mano. Con el Shadow DOM eso se rompe.
    AltaSwal.update() completo y Swal.close(resultado)Se usan para cambiar el texto o los botones mientras corre una tarea, y para cerrar con un resultado.
    AltainputAutoTrim (recortar espacios por omisión) y returnInputValueOnDenyCambia el valor que recibe tu código.
    MediaTemporizador: stopTimer, resumeTimer, toggleTimer, increaseTimer, getTimerLeftEs común con toasts que se pausan.
    MediaTipos de campo file, range y week; inputAutoFocusCubren subir un archivo o elegir un número rápido.
    MediaimageUrl (con ancho, alto y alt), iconHtml, progressStepsImágenes en el diálogo y asistentes de pasos sencillos.
    MediaenableButtons, disableButtons, enableInput, disableInputBloquear mientras se valida.
    BajareverseButtons, allowEnterKey, etiquetas aria-label de los botones, closeButtonHtml, loaderHtmlRetoques de comportamiento y texto.
    Bajatheme, target, draggable, template, didDestroy, position en modalesSe cubren con configure() y la API propia, o casi no se usan.
    Fuera del adaptadorSoporte RTL (derecha a izquierda)Sin soporte probado todavía.
    Fuera del adaptadorEnvoltorio para AngularHay hooks para React y plugin para Vue; Angular no.
    Fuera del adaptadorUso en producción y comunidadSweetAlert2 lleva años; nexus-dialogs es nuevo. Esa confianza solo se gana usándolo.
